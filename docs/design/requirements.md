# DataStream 需求文档

## 项目概述

**DataStream** 是一个基于 Go 语言实现的变更数据捕获（CDC）平台，从 Debezium 架构借鉴并重构，支持独立运行，无需强制依赖 Kafka。

### 项目目标

将 Debezium（Java CDC 平台）重构为 Go 项目，实现：
- 独立运行，不强制依赖 Kafka
- 直接从上游数据库同步到下游目标
- 保持 Debezium 的核心能力

---

## 功能需求

### 1. 数据源支持

支持 Debezium 目前支持的所有数据源：

| 数据源 | 说明 |
|--------|------|
| MySQL | Binlog 方式 |
| PostgreSQL | pgoutput/WAL 方式 |
| MongoDB | Change Stream 方式 |
| Oracle | LogMiner 方式 |
| SQL Server | CDC 方式 |
| MariaDB | Binlog 方式 |

### 2. 下游目标支持

- 支持 Debezium 目前支持的所有 Sink（MySQL、PostgreSQL、MongoDB、Elasticsearch、Redis 等）
- 额外支持 Kafka（可选）

### 3. 运行模式

- **单节点模式**：独立运行，适合小规模场景
- **集群模式**：多节点运行，支持任务调度和故障转移

### 4. 协调机制

- **可插拔架构**：协调后端可扩展
- **优先支持**：etcd、Consul

### 5. 数据传输

- **传输方式**：内存队列
- **进度持久化**：同步进度记录到存储，重启可恢复
- **数据安全**：重启丢数据不是问题，只要有进度记录可恢复

### 6. 进度存储

- **存储位置**：目标数据库
- **实现方式**：每个 Sink 在目标库中创建进度表
- **断点续传**：基于位点信息恢复同步

### 7. Schema 变更处理

- **兼容性检查**：Schema 变更时检查兼容性
- **不兼容处理**：不兼容时暂停任务并告警

### 8. 数据转换

- **基础过滤**：默认支持
- **可插拔转换器**：支持自定义转换器
- **脚本扩展**：后续实现（如 Lua、WASM）

## 同步范围

### 9. 同步级别

支持两种同步级别：

#### 9.1 Database 级别

**配置方式：**
- 单库：`["db1"]`
- 多库：`["db1", "db2", "db3"]`
- 通配符：`["*"]` - 源库新建 Database 自动发现并同步

**特性：**
- 开启 DDL 同步时，新表自动同步
- 支持表过滤规则（正则表达式）
- 支持忽略表规则

#### 9.2 Table 级别

**配置方式：**
- 指定表列表：`["db1.users", "db1.orders", "db2.products"]`

**特性：**
- 支持 API 动态添加/删除同步表
- 新增表时自动获取 Schema 并触发快照同步
- 精确控制同步范围

### 10. 快照与增量

#### 10.1 快照阶段

- **快照模式**：initial（首次）、when_needed（需要时）、never（从不）、always（总是）
- **多线程并发**：支持多线程并行执行快照
- **表分片**：大表支持按 Chunk 分片处理
- **锁模式**：none、shared、exclusive

#### 10.2 增量阶段

- **GTID 模式**：MySQL 支持 GTID
- **心跳机制**：保持连接活跃
- **重连机制**：支持自动重连

### 11. Sink 并发写入

- **多线程并发**：增量阶段 Sink 支持多线程并发写入
- **分发策略**：
  - Table：按表分发，同表事件有序
  - RowKey：按主键分发，同行事件有序
  - Database：按库分发，同库事件有序
  - RoundRobin：轮询分发
- **事务模式**：none、serial、parallel
- **缓冲区**：每个 Worker 独立缓冲区，定时刷新

## 非功能需求

### 12. 实现方式

- **语言**：Go
- **架构**：分层架构 + Go 并发模式
- **参考项目**：tiflow（PingCAP）

### 13. 实现规范

- **错误处理**：pingcap/errors 库，RFC 错误码
- **日志**：zap 结构化日志
- **配置**：TOML/JSON 格式
- **并发**：channel + goroutine 模式

## 推进方式

### 14. 开发策略

- **规划方式**：全量规划，分阶段实现
- **优先级**：先完整设计，按优先级分期开发
